## API, antarmuka lan arsitektur komunikasi (WP 1.11.3)

Kanggo mesthekake stabilitas sistem, keamanan lan skalabilitas, Nexus Gaja nderek arsitektur basis API lan acara-mimpin strictly.

### Prinsip dhasar
- **Ora ana akses database langsung:** Komponen komunikasi sacara eksklusif liwat antarmuka sing ditetepake (API utawa acara), ora tau liwat pitakon database langsung saka layanan liyane.
- **API Gateway:** Kabeh panjalukan klien eksternal liwat Gateway API sing nangani otentikasi, nuntun lan watesan tarif.
- **Abstraksi panyedhiya:** Layanan eksternal (model AI, panyedhiya pembayaran, mesin terjemahan) digabungake liwat lapisan abstraksi. Iki nyegah ketergantungan kabel lan ngidini panyedhiya fleksibel.

### Pola komunikasi
- **API Sinkron (REST/HTTPS):** Digunakake kanggo panjalukan langsung kayata login, setelan profil utawa terjemahan langsung.
- **Kedadeyan Asynchronous (Bus Acara):** Sistem saraf pusat Nexus Gaja kanggo proses decoupled (contone, `Message.Created` micu moderasi, terjemahan lan kabar ora sinkron).
- **Real-time (WebSocket):** Saluran khusus kanggo obrolan langsung lan status ngetik.

### Keamanan lan linuwih
- **Model Zero Trust:** Lalu lintas jaringan internal ora dipercaya kanthi otomatis; komunikasi layanan-kanggo-layanan sing sensitif mbutuhake otentikasi.
- **Idempotence & Outbox Pattern:** Operasi kritis (kayata sumbangan utawa pesen) dirancang kanggo idempoten kanggo nyegah macem-macem pangolahan lan nggunakake pola outbox kanggo mesthekake yen acara ora ilang sanajan ing transaksi database.
